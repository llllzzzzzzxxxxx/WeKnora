# 文档知识库多级文件夹方案（Document Knowledge Base Folders）

> 目标：解决 [Tencent/WeKnora#1311](https://github.com/Tencent/WeKnora/issues/1311) 中"数万到数十万文档"难以用标签组织的问题。
> 范围：**仅 document 类型知识库**。FAQ / Wiki 知识库不受影响（Wiki 已有自己的 `wiki_folders` 体系）。
>
> 状态：实现中（v1）。迁移、类型、仓储、检索过滤、knowledge 创建/移动、folder→knowledge 解析已经实现（见 §11 已完成清单）。剩余：service 实现 / dig 注入 / handler / router / 前端。

## 1. 背景与现状

- `KnowledgeBase.Type ∈ {document, faq, wiki}`，三种 KB 在 schema / 行为上各有差异。
- Wiki 知识库已经有完整方案：`wiki_folders` 表 + `WikiPage.FolderID`，迁移见 `migrations/versioned/000061_wiki_page_hierarchy.up.sql`，API 见 `internal/router/router.go:1779-1814`。
- 文档知识库的检索链路：`SearchTarget { Type, KnowledgeBaseID, KnowledgeIDs, TagIDs }` → `HybridSearch` → 命中 chunks → 返回。tag 维度已能缩小范围，但仍不能用"目录树"维度。

## 2. 设计目标

1. 文档 KB 支持多级文件夹（邻接表结构）。
2. 每个文档可挂在一个文件夹下；文件夹可空；根级 / 一级 / 多级均可。
3. 文件夹操作与 Wiki Folder 风格一致，但**独立表 / 独立路由**，不与 Wiki 共享代码。
4. 检索与对话能按文件夹子范围裁剪（"只在这个目录下查"），支持 issue #1311 的第二点诉求。
5. 不破坏现有数据：迁移添加可空字段，存量 `folder_id = ''` 表示"未分类"，与旧行为等价。
6. 不依赖 Wiki 专属配置：document KB 即使没开 wiki 也能用文件夹。

## 3. 数据模型

### 3.1 新表 `knowledge_folders`（已实现）

迁移：`migrations/versioned/000079_knowledge_folders.up.sql`（对应 down 在同目录；sqlite 变体在 `migrations/sqlite/000079_knowledge_folders.{up,down}.sql`）。

```sql
CREATE TABLE knowledge_folders (
    id                VARCHAR(36) PRIMARY KEY,
    tenant_id         BIGINT NOT NULL DEFAULT 0,
    knowledge_base_id VARCHAR(36) NOT NULL,
    parent_id         VARCHAR(36) NOT NULL DEFAULT '',  -- '' = root
    name              VARCHAR(255) NOT NULL,
    path              VARCHAR(1024) NOT NULL DEFAULT '', -- materialized "/"-joined name chain
    depth             INT NOT NULL DEFAULT 0,
    sort_order        INT NOT NULL DEFAULT 0,
    created_at        TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW(),
    updated_at        TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW(),
    deleted_at        TIMESTAMP WITH TIME ZONE
);

CREATE UNIQUE INDEX idx_knowledge_folders_parent_name
    ON knowledge_folders (knowledge_base_id, parent_id, name) WHERE deleted_at IS NULL;
CREATE INDEX idx_knowledge_folders_parent ON knowledge_folders (knowledge_base_id, parent_id);
CREATE INDEX idx_knowledge_folders_tenant_id ON knowledge_folders (tenant_id);
CREATE INDEX idx_knowledge_folders_deleted_at ON knowledge_folders (deleted_at);
```

> 结构与 `wiki_folders` 完全对称——这是有意的，方便将来如果合并两套体系时迁移；当前刻意不复用表，避免文档 KB 与 Wiki KB 在路由语义上混用。

### 3.2 扩展 `knowledges`（已实现）

```sql
ALTER TABLE knowledges ADD COLUMN folder_id VARCHAR(36) NOT NULL DEFAULT '';
CREATE INDEX idx_knowledges_folder_id ON knowledges (knowledge_base_id, folder_id);
```

`folder_id = ''` 表示"未分类"，与"无文件夹"的旧数据完全等价。

> 故意**不在 `knowledges` 上冗余 `folder_path`**——文档 KB 的列表/检索热路径只关心"是不是这棵子树"，冗余 path 会让重命名/移动成为全表同步。`path` 是 `knowledge_folders` 自己的字段，供 UI 排序/显示。

### 3.3 Go 类型（已实现）

`internal/types/knowledge_folder.go`：

- `KnowledgeFolderRootID = ""` —— 根节点 sentinel（与 wiki 同款）。
- `KnowledgeFolder` —— 邻接表 + materialized path。
- `KnowledgeFolderNode` —— 浏览器渲染条目，含 `DocumentCount` + `HasChildren`（注意：**用 `DocumentCount` 而不是 `KnowledgeCount`**，与字段命名一致）。
- `KnowledgeFolderTreeNode` —— 递归树（`Children []*KnowledgeFolderTreeNode`）。
- `KnowledgeFolderTree` —— 全树快照，根挂在 `Root` 字段（不引入合成节点）。
- `KnowledgeFolderCreateRequest` / `KnowledgeFolderUpdateRequest` / `KnowledgeFolderListResponse`。
- `MoveKnowledgeToFolderRequest { KBID, KnowledgeIDs, FolderID }` + `Response { Acknowledged, FolderID }`。
- `FolderScopeQuery { FolderIDs, IncludeDescendants }` —— chat 解析路径的输入。

`internal/types/knowledge.go` 同时新增：

- `Knowledge.FolderID string`（`gorm:"type:varchar(36);index;default:''"`）—— 单列索引已加，但实际过滤靠 `applyKnowledgeListFilter` 走 `(kb, folder)` 复合命中。
- `KnowledgeListFilter.FolderID *string` + `FolderScope FolderScope` —— 用 `*string` 区分"无过滤"与"只看根目录"。
- `FolderScope` 类型与两个值：`FolderScopeSelf = ""`（默认，单层），`FolderScopeTree = "tree"`（含后代）。
- 三个 `CreateKnowledgeFrom*` 服务方法新增 `folderID string` 参数（File/URL/PassageSync 走 helper/Manual 走直接传入），落地到 `Knowledge.FolderID`。

### 3.4 接口（已实现）

`internal/types/interfaces/knowledge_folder.go`（仓储）：

- `CreateFolder / GetFolderByID / GetChildFolderByName / ListChildFolders / ListAllFolders / UpdateFolder / DeleteFolder / ListDescendantFolderIDs`。
- 错误哨兵：`ErrKnowledgeFolderNotFound / ErrKnowledgeFolderConflict / ErrKnowledgeFolderNotEmpty`。

`internal/types/interfaces/knowledge_folder_service.go`（服务）：

- `ListChildFolders(kbID, parentID, pageTypes) → []KnowledgeFolderNode`（含文档数 + 子文件夹标记）。
- `ListFolderTree(kbID, parentID) → []*KnowledgeFolderTreeNode`（递归全树）。
- `CreateFolder / RenameOrMoveFolder / DeleteFolder`（name 校验、parent 存在、唯一性约束、深度上限）。
- `ResolveFolderIDs(kbID, folderIDs, includeDescendants) → []string` —— 仅扩展成 folder id 集合。
- `ResolveKnowledgeIDs(tenantID, kbID, folderIDs, includeDescendants) → []string` —— **扩展成 knowledge id 集合**，handler 单次调用即可。

`internal/types/interfaces/knowledge.go` 新增 `KnowledgeService` 方法：

- `MoveKnowledgeToFolder(tenantID, kbID, knowledgeIDs, folderID) → []string`（返回真正写入的 id 集合）。
- `ResolveFolderKnowledgeIDs(tenantID, kbID, *FolderScopeQuery) → []string`。
- `KnowledgeRepository` 新增 `ListKnowledgeIDsByFolderIDs / UpdateKnowledgeFolderID / UpdateKnowledgeFolderIDBatch / CountDocumentsByFolder`。

### 3.5 仓储实现（已实现）

`internal/application/repository/knowledge_folder.go`：

- `CreateFolder` / `GetFolderByID` / `GetChildFolderByName` / `ListChildFolders` / `ListAllFolders`：标准 GORM。
- `UpdateFolder`：写 `parent_id/name/path/depth/sort_order/updated_at`，`RowsAffected == 0` 映射为 `ErrKnowledgeFolderNotFound`。
- **`DeleteFolder` 用一条 SQL 同时做"非空校验 + 软删"**——`NOT EXISTS (SELECT FROM knowledges ...)` + `NOT EXISTS (SELECT FROM knowledge_folders ...)`，避免服务层预检与删除之间出现 race。失败回退区分 `NotFound` / `NotEmpty`。
- **`ListDescendantFolderIDs` 在 Go 端 BFS**，不依赖 PG/SQLite 方言差异，可移植。

`internal/application/repository/knowledge.go` 新增：

- `applyKnowledgeListFilter` 新增 folder 分支：
  - `nil` → 不过滤；`*FolderID == ""` → `folder_id = ''`；`FolderScope == FolderScopeTree` → `folder_id IN (SELECT id FROM knowledge_folders WHERE knowledge_base_id = ... AND (id = ? OR path = ? OR path LIKE '?/%'))`；否则 `folder_id = ?`。**这条子查询被 `(knowledge_base_id, folder_id)` 复合索引覆盖。**
- `ListKnowledgeIDsByFolderIDs / UpdateKnowledgeFolderID / UpdateKnowledgeFolderIDBatch / CountDocumentsByFolder`：标准实现，含 tenant / KB / soft-delete 三重 scope 保护。

### 3.6 服务实现（部分已实现）

`internal/application/service/knowledge.go`：

- 注入 `folderRepo / folderService` 两个新依赖。
- **`MoveKnowledgeToFolder`**：先校验 folder 存在（`ErrKnowledgeFolderNotFound → 404`），再 `GetKnowledgeBatch` 拿到当前 tenant 下的全部 ID，过滤出 `kb_id` 匹配项，`UpdateKnowledgeFolderIDBatch` 写回，返回 `acknowledged`。
- **`ResolveFolderKnowledgeIDs`**：nil / 空 folderIDs 直接返回；`IncludeDescendants` 时先调 `ListDescendantFolderIDs` 扩展，再 `ListKnowledgeIDsByFolderIDs` 拿到文档 id 集合。

`internal/application/service/knowledge_create.go`：

- `CreateKnowledgeFromFile/URL/PassageSync/Manual` 全部接受 `folderID string`，落库前先 `GetFolderByID` 校验存在。

## 4. HTTP API（未实现）

设计路由挂在 `/api/v1/knowledge-bases/:kb_id/folders`，与 Wiki 的 `/api/v1/knowledgebase/:kb_id/wiki/folders` 区分：

```
GET    /api/v1/knowledge-bases/:kb_id/folders?parent_id=&recursive=
POST   /api/v1/knowledge-bases/:kb_id/folders
PUT    /api/v1/knowledge-bases/:kb_id/folders/:folder_id
DELETE /api/v1/knowledge-bases/:kb_id/folders/:folder_id?force=
GET    /api/v1/knowledge-bases/:kb_id/folders/tree              # 全树
POST   /api/v1/knowledge-bases/:kb_id/folders/move-knowledge    # 批量挂载文档
```

Handler：`internal/handler/knowledge_folder.go`（新文件）。注册函数：`internal/router/router.go` 新增 `RegisterKnowledgeFolderRoutes`，紧邻 `RegisterKnowledgeRoutes` 调用，参考 `RegisterWikiPageRoutes`（路由 1779-1814 行）的 group 风格。

RBAC：读 = `Viewer()`，写 = `OwnedKBOrAdmin()`（复用现有 guard；document KB 不走 wiki 专属 guard）。

文档管理接口同时改造：

- `POST /api/v1/knowledge-bases/:kb_id/knowledge/file` / `/url` / `/manual` 的 multipart / body 多加一个 `folder_id` 字段。
- `POST /api/v1/knowledge-bases/:kb_id/knowledge/move`（KB 之间移动）独立保留，**不**与"在同 KB 内换文件夹"混用。
- `GET /api/v1/knowledge-bases/:kb_id/knowledge` 的 `KnowledgeListFilter` 同步生效 `folder_id + folder_scope`。

## 5. 检索范围

与 Wiki 不同，本方案**不在 `SearchTarget` 加字段**——采用子任务 [Map retrieval scope flow](6694cf36-db55-4aa3-94dd-ecf04141b7d6) 推荐的更轻量路径：

1. `@folder` mention 或 `KnowledgeListFilter.FolderID` 在 service 入口拿到 `FolderScopeQuery`。
2. 调 `ResolveFolderKnowledgeIDs(tenantID, kbID, scope)` 展开成 `[]string`（包含后代或仅本目录）。
3. 走现有 `SearchTarget { Type: knowledge, KnowledgeIDs: ids }` 路径——**`SearchTarget` / `SearchParams` / retriever SQL 一行都不用改**。

收益：

- 向量 / 关键词索引零改动，过滤完全在 SQL 层 IN 完成（命中 `(kb, folder_id)` 索引）。
- 会话侧 `SessionLastRequestState` 持久化 `folder_scope`（folder id 列表 + include_descendants），让用户上次选的目录在下次进入会话时仍生效。

## 8. 向后兼容与边界

- 存量 `knowledges.folder_id = ''` → 仍走"无文件夹"分支，与今天等价。
- 删除 KB 时 `knowledge_folders` 行通过迁移期 cleanup 或 service 显式删除处理（与 wiki 一致不加 FK，靠 service 保证）。
- 服务类型校验：document KB 可用；faq / wiki 类型返回 400（与 wiki folder 行为一致）。
- 删除文件夹语义：仅当空文件夹可删；本方案**没有 `force=true`**——若要"清空子树文档 folder_id 但不级联"，需要 service 加 `force` 参数并把子树文档 `folder_id` 置空（v1 不实现，等用户提需求再加）。
- 上传时的 folder 校验：所有 `CreateKnowledgeFrom*` 路径都先 `GetFolderByID` 校验，不存在的 folder_id 返回 404。

## 9. 与 Wiki Folder 的关系

| 维度 | Wiki Folder | Document Folder（本方案） |
|------|-------------|---------------------------|
| 表 | `wiki_folders` | `knowledge_folders` |
| 关联实体 | `wiki_pages.folder_id` | `knowledges.folder_id` |
| 路径缓存 | materialized `path` | 同左 |
| 删除级联 | 不级联 | 不级联；v1 无 force |
| 检索维度 | Wiki 专属筛选 | 通过 `ResolveKnowledgeIDs` → 现有 `KnowledgeIDs` 路径 |
| DTO 命名 | WikiFolder\* | KnowledgeFolder\*（用 KnowledgeFolderNode.DocumentCount，而非 WikiFolderNode.PageCount） |

刻意保持独立，避免文档 KB 误开 wiki 才拥有文件夹，也避免 wiki 关闭后文件夹消失。

## 10. 风险与开放问题

1. **并发移动** — 同一文件夹被同时重命名/移动时，事务隔离需要测试。`DeleteFolder` 已用单 SQL 原子保证；`RenameOrMoveFolder` 需要 `SELECT ... FOR UPDATE` 或更高隔离级（建议在 service 实现里补）。
2. **大批量挂载性能** — `MoveKnowledgeToFolder` 单次最多允许 500 个 ID（与 `BatchUpdateKnowledgeTags` 对齐），超出分批。`UpdateKnowledgeFolderIDBatch` 已用单 SQL。
3. **CSV/批导** — DataSource 批量导入是否需要指定文件夹？建议 v1 留 `folder_id` 可选，未指定则放根，v2 单独支持导入模板里指定。
4. **KB 共享** — 共享 KB 时，文件夹结构是否对被共享方可见？倾向是（被共享方也应是 Viewer），由 RBAC middleware 自然处理。
5. **深度上限** — 当前 types 里**未定义 `KnowledgeFolderMaxDepth`** 常量，service 实现时需要补；建议 `= 5`（与方案稿一致，文档库目录比 wiki 页面更深）。
